# ANIIMOGG P1-B — Team Builder PRD

版本：1.0 · 日期：2026-11-11 · 状态：PLANNED_NOT_IMPLEMENTED。

本文是下一阶段开发基线。本轮仅交付规划文档，没有Team Builder页面、功能代码或新路由上线。基线为P1-A.1：130条形态、118 Basic + 12 Prismana、稳定entityId、四语言官方名称、原收藏v2协议。

## 1. 产品目标与事实边界

让玩家创建多个自己的规划清单，整理成员顺序，比较已收录元素与定位的覆盖情况，并在本机保存、导出、导入与分享。覆盖统计只描述公开索引字段，不表示战斗优势、合法出战编队、最优比例或强度排名。

游戏内角色编队上限：**UNKNOWN，尚无足够的当前官方证据**。

2026-11-11查阅的[官方历史测试FAQ](https://www.yimo.com/newslist/detail/hj9zb1yc)描述了编队管理操作，但正文属于2025年删档测试，不能证明当前人数上限；页面时间标签与正文测试时间也不一致。[9月23日官方更新公告](https://www.aniimo.com/newslist/detail/100145)的四人合作指玩家人数，不作为角色槽位数量。没有使用第三方工具的“四只”设计作为官方证据。

v1统一称“自定义规划清单”。可收录最多130个不同entityId，这是本站当前数据规模下的工具保护上限，**不是游戏编队上限**。不显示未经核验的固定出战槽位，不把Compendium比较上限3解释为队伍人数。未来获得带版本/模式/日期的官方证据后，另行设计规则，不自动删除超出新规则的已有清单。

## 2. 目标用户与成功标准

- 新玩家：从图鉴找到角色，保存自己考虑使用的组合。
- 已有收藏的玩家：从当前收藏中挑选成员，收藏与队伍互不改写。
- 多方案玩家：对照两到三个方案的成员、元素、定位和缺失资料。

验收以可复现任务完成率、数据一致性、恢复能力与性能门禁为准，不新增遥测、账号或统计服务来采集队伍。成功任务：创建命名清单 → 搜索并添加成员 → 调整顺序 → 查看覆盖 → 保存刷新 → 导出/导入 → 打开分享预览。全过程不要求登录。

## 3. 信息架构与页面结构

下一阶段拟新增四语言基础工具地址：`/team-builder/`、`/zh-cn/team-builder/`、`/zh-tw/team-builder/`、`/ja/team-builder/`。当前阶段不创建。

| 区域 | 内容与主要操作 |
|---|---|
| 工具首页 | 简介、数据范围/核验日期、已有清单、新建、导入 |
| 清单编辑 | 名称、保存状态、成员顺序、添加角色、撤销删除 |
| 角色选择面板 | 复用图鉴搜索/元素/定位/形态筛选、详情、添加/已添加 |
| 成员区域 | 当前语言名称、编号、形态、目录组、元素/定位、详情、上移/下移/移除 |
| 元素覆盖 | 已覆盖、未覆盖、重复出现的元素、未知成员 |
| 定位覆盖 | 已覆盖、未覆盖、重复定位、数据不足提示 |
| 多方案比较 | 最多3个清单，并列成员、覆盖集合与资料完整性 |
| 保存与分享 | 本地保存、导出JSON、导入预览、复制一个清单的分享链接 |

桌面使用成员区与分析区两列；手机采用单列，“成员/分析”切换与角色选择抽屉。保留本站颜色、圆角、字体和卡片语言，不做密集后台表格。空状态先展示“添加角色”，不要求填写复杂配置。

## 4. 完整用户流程

1. 首次打开显示空状态、仅本地保存说明和数据范围；新建后默认名称按当前界面语言生成，可重命名。
2. 打开角色选择，搜索任一官方语言名称/英文/别名/原sourceRecordId/entryKey；多维筛选规则继承Compendium：维度内OR，维度间AND。
3. 先看详情或直接添加。重复添加同一entityId不产生第二份成员，提示“已在清单中”。不同形态即使同名仍是不同entityId；同时列入规划不宣称游戏内可同时出战。
4. 返回编辑页，使用上移/下移按钮调整顺序；拖拽仅作桌面增强，不能成为手机唯一操作方式。移除成员后可撤销，焦点落到相邻成员或添加按钮。
5. 分析随成员变更更新；修改名称不重算角色字段。保存成功后标记“已保存在此浏览器”，失败则标记“仅本次会话”，仍可导出。
6. 刷新恢复已保存清单及成员顺序；切换语言只改变界面和角色名称，不改变成员身份、用户自定义名称或收藏。
7. 勾选2或3个清单进入比较；第4个被拒绝并明确提示。比较不改变任何清单或Compendium三形态比较状态。
8. 导出单个/全部清单；导入先显示名称、成员数、未知ID、冲突处理与将新增数量，确认后默认追加，不覆盖原方案。
9. 分享默认只包含当前清单的成员与数据版本，队伍名称可选择包含；在复制前说明链接可被持有者读取。打开链接先预览，再由用户保存为新的本地清单。

## 5. 交互与状态规则

- 本地最多20个清单，名称trim后1–80个Unicode字符；这是工具限制，不是游戏限制。允许同名，列表附修改时间帮助区分。
- 成员按entityId唯一，顺序来自数组。不得按编号、名称或猜测的物种关系合并。
- 清单删除需针对具体名称确认，提供本地撤销/上一版本恢复点；存储失败不显示删除已保存。不要触碰收藏v1/v2键。
- 清单编辑实时更新内存，写存储可短时合并，失焦/切换清单时完成待保存写入。保存状态需如实区分成功、保存中、失败。
- 选角面板保留该次搜索/筛选，关闭再开不重置成员；“清除筛选”不清空清单。
- 未知entityId保留占位与ID，可移除，也可原样导出；不静默删除、不用同编号其他角色替换。
- 当前源没有species/family/parent关系、可靠战斗数值或完整模式约束，相关分析不提供。

## 6. 覆盖算法与展示文案

直接使用规范化记录的`elements`与`roles`，词表来自既有官方术语，不增加第二套角色库。

每个元素/定位的数量为包含该标签的不同成员数；多标签成员分别贡献到各标签，但同一标签对同一成员只计一次。已覆盖为已知标签的并集；重复为成员数大于1；未覆盖为本次索引词表减去已知并集。

资料缺失、未知ID、空数组或新出现的未映射标签均单独列出。空数组不能自动解释为“该角色没有元素/定位”；必须标记数据不足。存在未知成员时，“未覆盖”只能表述为“已知资料中未覆盖”，不可断言全队绝对没有该标签。

展示“已知成员n / 总成员m”“已覆盖x种索引元素”，不展示战斗分数、推荐最优比例、胜率或克制推断。重复元素只描述重复，不标为优点/缺点。

## 7. 四语言与移动端

EN、简中、繁中、日文同步提供完整UI、空状态、错误提示、导入/导出、比较和来源提示。直接复用P1-A.1官方localizedNames/evidence；缺失时英文回退，禁止机器翻译或机械简繁转换冒充官方名称。用户自定义名称不自动翻译。

覆盖360×800、390×844、430×932、768×1024、1265×712、844×390。主要按钮至少44×44 CSS px；不依赖hover。抽屉关闭按钮可持续触达，内容可滚动，比较表格仅自身横滚；底栏有安全区留白且不遮挡添加/移除/搜索。缩小可视区域模拟与真实软键盘测试分别记录。

弹层需标题、合理初始焦点、Tab限制、Escape关闭及触发点焦点恢复；成员重排可键盘完成。保存/添加/覆盖变化用适度aria-live提示，aria-pressed反映实际选中状态，不用颜色独自表达覆盖。

## 8. 保存、分享、SEO与隐私

独立版本化本地存储，不接触收藏数据，不新建账号、后端或云同步。损坏JSON、禁用存储、配额不足时保留原值并提供会话模式/导出，不静默重置。

JSON仅保存清单名称、成员entityId、顺序和版本元信息；不导入用户提供的角色数值或外部资源URL。导入采用白名单schema、大小/数量限制、冲突预览，原子追加。详情字段始终重新解析本站规范化数据。

分享采用基础语言路径加URL Fragment；无队伍query页面，不生成可索引的每队URL。Fragment不是加密，也可能被页面脚本读取；不承诺绝对隐私。默认不含自定义名称，不含收藏、未知浏览器数据、账号或其他清单。没有自动上传或代发消息。

下一阶段工具初始采用noindex,follow、canonical指向无fragment基础语言页、四语言hreflang及x-default；不把分享状态写入metadata/JSON-LD。初始不加入Sitemap，当前168 URL保持。是否转为索引页面须基于完整公开工具内容另行处理，不在本轮改变robots/noindex配置。

## 9. 性能预算与开发优先级

公共JS≤20,000 B、公共CSS≤50,000 B；图鉴原20,000 B JS合计/50,000 B CSS合计/250,000 B HTML门禁保持。Team Builder拟定专用JS≤20,000 B、页面全部首方JS合计≤20,000 B、合计CSS≤50,000 B、专用CSS≤10,000 B、HTML≤250,000 B、按需规范化数据≤100,000 B。首页/长文75,000 B预算不变。预算均指未压缩实际字节，不靠gzip掩盖。

先实现数据与存储、选角/顺序、覆盖分析；随后比较、导入/导出/分享；最后补齐四语言、双引擎移动验收、性能与Preview/Production门禁。具体依赖、测试和阶段出口见配套技术方案及验收标准。

## 10. 明确不做

不做战斗模拟、最强配队、伤害/胜率、强度榜、未经核验的元素克制结论、自动推荐最优比例、技能/装备系统、游戏账号读取、所有权同步、云端分享服务、多人协作、付费设备测试或新服务器。当前阶段也不实现任何Team Builder代码。
