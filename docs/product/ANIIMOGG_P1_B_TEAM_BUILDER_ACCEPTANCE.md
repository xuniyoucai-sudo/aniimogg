## 2. 编辑与保存流程

四语言分别执行创建 → 命名 → 搜索 → 详情 → 添加三名不同成员 → 重排 → 移除 → 撤销 → 保存 → 刷新恢复 → 比较 → 导出 → 导入 → 分享预览。

| ID | 操作/输入 | 必须观察的结果 |
|---|---|---|
| E01 | 新建、重命名（空/空格/81字符/有效80字符） | 有效值保存，非法值明确提示且不损坏旧值；中文/日文按Unicode字符计数 |
| E02 | 选择已在清单中的entityId | 无重复成员、无重复事件，提示已添加；收藏不变 |
| E03 | 搜索Emberpup/小炭犬/小炭狗/ワンタ/原ID/entryKey/Witchin | 目标entityId与图鉴一致；跨语言姓名可搜索，原别名保留 |
| E04 | 元素、定位、形态多条件与清除 | 沿用OR/AND规则，清除只清筛选，不清成员或收藏 |
| E05 | 键盘和触屏重排首/中/末成员 | 顺序正确、边界按钮禁用、保存后刷新仍一致；不依赖拖拽 |
| E06 | 移除成员、撤销、删除清单确认与恢复 | 状态/焦点/保存提示一致；可恢复上一版本，不误删其他清单 |
| E07 | 保存20个清单，再创建第21个 | 清楚提示工具限额，不覆盖旧清单；不称为游戏限制 |
| E08 | 两标签页同时修改 | 发现外部变更并提示，不能静默覆盖未保存内容 |
| E09 | 添加/编辑/导入/比较全过程 | 收藏v1/v2键与未知收藏ID完全保持，比较状态互不污染 |

## 3. 覆盖与比较算法

使用真实规范化fixture，并对缺失字段建立明确测试副本，不把测试副本写回生产数据。

| ID | 场景 | 必须观察的结果 |
|---|---|---|
| A01 | Emberpup + Flameruff（均Fire/DPS） | 元素并集只有Fire、重复Fire计数2；定位DPS计数2；不计作2种元素 |
| A02 | 选择真实多元素记录 | 各元素各计1个成员，同标签在单记录内重复仍只计1 |
| A03 | 空清单 | 覆盖0、无NaN/除零、清楚空状态；不提示队伍弱或不合法 |
| A04 | 已知成员+未知ID | 已知统计正确，总成员仍含未知；“已知资料中未覆盖”与未知清单明确 |
| A05 | 空/缺失elements或roles、未映射新标签 | 分别记录缺失维度，不将缺失当没有，不归入相似已知标签 |
| A06 | 比较1/2/3清单，第4个 | 最多3个清单，拒绝第4个有提示；移除/清空不改原清单 |
| A07 | 相同覆盖但成员不同的两个清单 | 如实展示差异，无胜负/分数/最佳比例/战斗力结论 |

## 4. 存储与安全导入

| ID | 场景 | 必须观察的结果 |
|---|---|---|
| S01 | localStorage读/写禁用、QuotaExceededError | 内存可继续操作并导出，旧值原样保留，显示未保存 |
| S02 | 损坏JSON、非对象、未知version、非法成员类型 | 不静默清空，不部分迁移/覆盖；错误说明可理解 |
| S03 | 合法导出再导入 | 成员与顺序等价、四语言切换不改变身份；默认追加 |
| S04 | team UUID冲突/重名/重复memberId | 预览冲突策略；新team ID不覆盖旧，重复成员拒绝，重名可区分 |
| S05 | 超200,000 B、21清单、131成员、深度9、超长ID | 校验失败前无存储写入；限额文案明确为工具限制 |
| S06 | `__proto__`/多余stats或URL/脚本样式字符串 | 非schema字段拒绝，字符串安全展示；无执行/原型污染/外部网络请求 |
| S07 | 格式有效的未知entityId导入/保存/导出 | 原样保留且显示Unknown，不按名称/编号猜测替换 |
| S08 | 导入批次中一条非法或写存储失败 | 原文档完整不变，不出现部分导入；允许重新选择合法条目后确认 |

## 5. Fragment、SEO与隐私

| ID | 场景 | 必须观察的结果 |
|---|---|---|
| U01 | 分享一个清单，未选择附带名称 | 只含版本与该清单成员；不含名称/其他清单/收藏/账号数据 |
| U02 | 含中日文字名称的合法载荷 | UTF-8往返准确；用户选择附带名称才写入链接，复制前说明公开性 |

## 6. 移动、键盘与浏览器矩阵

EN、zh-CN、zh-TW、ja × 360×800 / 390×844 / 430×932 / 768×1024 / 1265×712 / 844×390 × Chromium / 匹配版WebKit。每个组合至少执行上述完整主流程、折叠筛选、弹层滚动/关闭、比较内滚、收藏互不干扰与刷新恢复。

- 主要操作44×44 CSS px，elementFromPoint命中正确，无相邻误触，无hover依赖。
- 页面scrollWidth≤viewport+1；比较区域可内部横滚；底栏不遮挡搜索、末个成员或删除按钮。
- 搜索聚焦/输入/清除/结果反馈正常；实际系统软键盘与缩小视口模拟分别记证据，不能互相替代。
- 弹层标题/焦点/Tab限制/Escape/关闭后焦点恢复正常；重排与移除后焦点可继续操作；aria-pressed和aria-live符合真实状态。
- 页面与弹层滚动不锁死，横竖屏切换、底部安全区和短横屏关闭按钮可触达。
- 先检查真实设备/模拟器；能用则优先实机。没有则标NOT AVAILABLE，并记录具体引擎/版本，不伪称iPhone/Android验收。

## 7. 性能与资源门禁

公共JS≤20,000 B，公共CSS≤50,000 B；图鉴原全部预算保持。Team专用JS≤20,000 B且页面首方JS总和≤20,000 B，专用CSS≤10,000 B且总CSS≤50,000 B，HTML≤250,000 B，按需同源数据≤100,000 B；首页/长文≤75,000 B。不得改预算来消除失败。

验证所有实际资源SHA-256与manifest一致、MIME正确、依赖存在、无固定query/本地绝对路径/Preview资源混入。相同输入重复构建URL稳定，修改共享模型使消费者import及最终hash正确更新；旧HTML+旧哈希资源仍可工作。普通页面不加载Team资源。

CPU4倍减速记录搜索、筛选、覆盖更新、详情和比较的样本/测法；处理器p95≤100ms、最大≤250ms，含两动画帧观察值≤500ms。测首屏、130条选择数据、内存/DOM重复绑定与清单切换，不把实验室数字写成真实CWV。

应用初始化异常、应用JS/CSS/JSON请求失败均阻断。图片主动取消与已归因的第三方统计异常必须保留原始事件、独立验证图片字节/可见解码，单列警告；未知源异常不能直接归类为广告/统计忽略。不得禁缓存、清生产缓存或修改CSP制造通过。
