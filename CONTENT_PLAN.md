# Aniimo Guide publishing and update plan

This schedule keeps the site useful between the initial content launch and the game's release. Dates are editorial targets, not promises from the game publisher.

## Pre-launch cadence

| Date | Editorial action |
| --- | --- |
| 2026-08-29 | Check the official download page and stores for preload details; update the download and server-time guides only if confirmed. |
| 2026-08-30 | Recheck the official Wiki roster and refresh the confirmed Aniimo index. |
| 2026-08-31 | Check official FAQs/store listings for cross-save and account-linking details. |
| 2026-09-01 | Completed: rechecked the 13 Steam text languages and four full-audio languages; published the PS5 pre-order and accessibility guides, expanded the Time to Aniimo event instructions, added launch-time tables, localized RSS feeds and sourced news entries. |
| 2026-09-02 | Recheck PC requirements and Steam Deck status. |
| 2026-09-03 | Review Egg Heist rules; retain the Beta label until release behavior is tested. |
| 2026-09-04 | Refresh elements, roles, evolution and forms from the official Wiki. |
| 2026-09-05 onward | Publish or materially refresh one useful page every one or two days. Prioritize official news, beginner questions, regions and map preparation. |

## Launch windows

- 2026-09-16: test the PC and console release, then update affected pages from **Beta** or **Official** to **Release-tested** only after hands-on verification.
- 2026-09-16 to 2026-09-22: review launch time, download size, servers, crossplay, controls, performance and beginner content daily.
- 2026-09-23: test the mobile release separately and update mobile download, requirements, crossplay and account information.
- First launch week: publish a concise daily change log; correct outdated beta claims before adding new speculative content.

## Ongoing cadence

- Check official patch notes, events and store listings on every update day.
- Review high-traffic guides within 24 hours of a relevant patch.
- Review evergreen guides monthly even if no patch mentions them.
- Use Search Console and Bing Webmaster Tools queries to choose the next article or expansion; do not create thin pages only to target keywords.

## Status workflow

1. **Official** — directly supported by a current first-party announcement, store listing or official Wiki entry.
2. **Beta** — observed or documented in a beta; it may change before or at launch.
3. **Release-tested** — verified against the public release by the editorial team, with platform and game version recorded.

Every material update must change `updated`, confirm `version` and `status`, add a short change-log entry, recheck sources, internal links, localized metadata, image alt text and image attribution. Unknown information stays explicitly marked as not announced; it must never be filled with an estimate presented as fact.

## Image workflow

- Use first-party press assets only when their usage and source are clear, or create an original site graphic/screenshot.
- Never copy imagery from another guide site.
- Export article images as WebP or AVIF, set intrinsic width and height, write meaningful alt text in all three languages, and show a source/credit caption.
- Retain the original working file and source URL in the editorial archive when adding an official asset.
